# 接入小屋网页（xinchaomind.uk）

这份文档解决一个问题：把你自己自托管的心潮实例，接到公开可视化网页 **xinchaomind.uk**（俗称「小屋」），在浏览器里看自己心潮的动态心智可视化，而不用自己写前端。

连接方式是 **Dashboard 令牌模式**：小屋的服务端拿着你给的口令，去只读访问你心潮的 Dashboard 接口。你的心潮不需要把 `SERVICE_TOKEN` 交出去，浏览器也永远接触不到它。

> 如果你的心潮和浏览器在**同一台机器**上（自己电脑、手机 Termux），可以不走小屋、让浏览器直接读本机，见 README 的「浏览器直连」一节。本文是给有公网地址、想用公开小屋看可视化的人。

---

## 1. 前置：心潮要有公网 HTTPS 地址

小屋是**服务端代访问**：小屋的服务器拿着你的口令去连你的心潮。所以你的心潮必须有一个小屋服务器能到达的公网 HTTPS 地址，指向本机的 `18110` 端口。

- ⚠️ **坑**：Compose 默认只映射到 `127.0.0.1:18110`，别人的服务器永远到不了你的 `127.0.0.1`。这不是配置错，是物理上做不到 —— 你必须自己在前面架一层公网 HTTPS。
- ⚠️ **坑**：不要直接把裸的 `18110` 端口开放到公网。前面必须有 HTTPS。

常见做法（任选其一）：

- **Cloudflare Tunnel**：`cloudflared tunnel --url http://127.0.0.1:18110`，或配好命名隧道绑定自己的域名。
- **Tailscale Funnel**：`tailscale funnel 18110`。
- 自己的 Nginx / Caddy 反向代理 + 证书。

拿到地址后先自测一下（把域名换成你的）：

```bash
curl https://你的心潮域名/health
```

能返回健康状态和版本，才说明公网链路通了，再往下配。

---

## 2. `.env` 配置

在心潮的 `.env` 里打开 Dashboard 并填好这几项：

```env
DASHBOARD_ENABLED=true
DASHBOARD_ACCESS_TOKEN=<自定义口令，≥32字符，别泄露>
DASHBOARD_PUBLIC_BASE_URL=https://你的心潮域名   # 实例根地址，别加 /mcp
DASHBOARD_ALLOWED_ORIGINS=https://xinchaomind.uk
```

逐条说明：

- `DASHBOARD_ACCESS_TOKEN`：Dashboard 专用口令，**必须和 `SERVICE_TOKEN` 不同**。它只能换到一个只读会话，读不了原始状态、也调不了 MCP。可以用 `openssl rand -hex 32` 生成。
  - ⚠️ **坑**：这个口令要填给小屋，等于交给小屋服务端。所以它绝不能等于 `SERVICE_TOKEN`；一旦某天想撤销，改掉这一项重建即可，不影响服务主密钥。
- `DASHBOARD_PUBLIC_BASE_URL`：填**实例根地址**，也就是 `/health` 前面那一截。
  - ⚠️ **坑**：别在结尾加 `/mcp`、`/dashboard` 或任何路径，也别带末尾多余的斜杠。填错会导致小屋拼出来的接口地址 404。
- `DASHBOARD_ALLOWED_ORIGINS`：填 `https://xinchaomind.uk`。这是浏览器侧跨源白名单，只放行小屋这一个来源。
  - 多个来源用逗号分隔；**不要**写 `*`。

改完保存。

---

## 3. 重启让配置生效

```bash
docker compose up -d --force-recreate
```

- ⚠️ **坑**：只改 `.env` 后跑普通的 `docker compose up -d`，Compose **不一定会重建容器**，新的环境变量可能没被读进去，你会以为「配了没用」。改过 `.env` 就加 `--force-recreate`，强制重建，环境变量才真正生效。

重启后再确认一次 `/health` 正常。

---

## 4. 在小屋登录并连接

1. 打开 **https://xinchaomind.uk**，登录。
2. 找到「连接 / 接入」入口。
3. 填两样东西：
   - **你的心潮域名**：和 `DASHBOARD_PUBLIC_BASE_URL` 一致的实例根地址（`https://你的心潮域名`，不加 `/mcp`）。
   - **Dashboard 口令**：也就是你 `.env` 里的 `DASHBOARD_ACCESS_TOKEN`。
4. 提交。小屋会用这个口令去你的心潮换一个只读会话，成功后就能看到你心潮的动态心智可视化了。

连接成功后，小屋看到的都是**默认脱敏**的投影：十二维驱动力、念头池、疲惫/睡眠、结构化时间线等。梦境摘要与余韵文字默认隐藏（由 `DASHBOARD_INCLUDE_PRIVATE_TEXT` 控制，默认 `false`）。

## 5. 关于记忆星图（重要，先读这段再报 bug）

小屋「时光页」里有一块**记忆星图**（memory-map / 星图）的可视化。

⚠️ **独立版心潮本身不捆绑 Ombre Brain(OB) 记忆库**，所以：

- **独立版默认没有星图数据。** 你按上面步骤接好小屋、一切正常，时光页仍然会显示「**未接入 OB / 星图不可用**」—— 这**是正常的、不是故障**，不是你口令填错了，也不是小屋坏了。
- 星图的数据来自一套**你自己另外跑的 OB**。心潮独立版只在你**主动接上 OB 并打开读取开关**之后，才会把星图点亮。

从 **2.7.0** 起，心潮内部为星图加了一层 HTTP 接口（都在 Dashboard 鉴权之后、由环境变量 `OMBRE_READ_ENABLED` 控制）：

- `GET /dashboard/api/memory-map`
- `GET /dashboard/api/memory-bucket?id=<桶id>`

没接 OB（或 `OMBRE_READ_ENABLED=false`）时，这两条路由会**干净地返回** `{available:false, reason:...}`，小屋据此显示「未接入 OB / 星图不可用」，而不是抛错。所以你在日志里看到的是一条明确的「不可用」而非报错，这也是预期行为。

**想要星图怎么办？** 你需要：

1. 自己跑一套 OB；
2. 在心潮 `.env` 里把 OB 接上（`OMBRE_MCP_URL` / `OMBRE_MCP_TOKEN` / `OMBRE_READ_ENABLED=true`）；
3. 给 OB 打一个小补丁，让它能吐出结构化星表。

这三步在另一份文档里有完整步骤和排障表：

👉 **《连接 Ombre Brain 记忆库·星图接口层改造》**（`docs/连接OmbreBrain与星图接口层改造.md`）

## 常见问题速查

| 现象 | 多半是 |
| --- | --- |
| 小屋连不上、超时 | 心潮没有公网 HTTPS 地址，或映射还停在 `127.0.0.1`；先用外网 `curl /health` 验证 |
| 小屋提示口令无效 / 401 | 填的是 `SERVICE_TOKEN` 而不是 `DASHBOARD_ACCESS_TOKEN`，或口令没重建生效 |
| 接口 404 | `DASHBOARD_PUBLIC_BASE_URL` 结尾多加了 `/mcp` 或路径 |
| 改了 `.env` 没反应 | 用了 `up -d` 没加 `--force-recreate` |
| 时光页显示「未接入 OB / 星图不可用」 | **正常现象**，独立版不带 OB，要星图见上面第 5 节 |
